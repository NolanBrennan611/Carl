# Carl — Implementation Plan (for the implementing model)

Status: **Approved design baseline v1.0** (2026-10-25)
Read `CLAUDE.md` first. Implement **one phase at a time, in order**. Each phase ends runnable, tested, and committed. Don't start the next phase until the current phase's acceptance criteria pass and the user approves.

---

## 0. Ground rules

1. The docs in `docs/` are authoritative. If something is missing or contradictory, **stop and ask**; don't invent architecture. Small local choices (helper names, private functions) are fine.
2. Layering rule: `domain`, `services`, `repositories`, `scheduler`, `db` never import `discord` (enforced by `tests/unit/test_import_boundaries.py`).
3. Time comes only from the injected `Clock`. Never call `datetime.now()`, `date.today()`, or `time.time()` outside `clock.py`. Exception: `asyncio.sleep` in the loop.
4. SQL only in `repositories/` and `db/`, always parameterized.
5. Every service method that writes uses `async with db.transaction():` (`BEGIN IMMEDIATE`).
6. Tests first for `domain/` and `scheduler/` logic. Use `tests/fakes.py` (`FakeClock`, `FakeNotifier`), never real Discord.
7. Runtime dependencies are exactly: `discord.py~=2.7`, `aiosqlite`, `tzdata`, `python-dotenv`. Dev: `pytest`, `pytest-asyncio`, `pytest-cov`, `ruff`. Ask before adding anything.
8. Commands: `uv sync`, `uv run pytest`, `uv run ruff check .`, `uv run ruff format .`, `uv run python -m carl run`.
